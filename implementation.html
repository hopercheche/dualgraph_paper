Implementation specification

One frontend, two frozen backend modes

Conventional + RAG and DualGraph-OSCE share the platform; the method difference lives in evidence and rule execution.

Separate a method specification from a tested result

This page describes the required A/B contract. It does not certify that every block is deployed, that every compiled rule is faculty-approved, or that comparative effects have been measured. Existing station controls and source evidence are retained; readiness requires the checks below.

The executor’s public contract

judge(rule_graph, evidence_graph, session_state) →
  actor_view:
    required_answers, permitted_facts, forbidden_facts, allowed_prompt_ids
  assessment_view:
    criterion_status, applicable_effects, correction_state, review_reasons
  proof:
    rule_ids, evidence_ids, bindings, temporal_results
  next_state:
    revision, active_conditions, current_regimen, delivered_prompt_counts

The role generator receives actor_view only. Private answers and grade consequences are not exposed through that projection. Assessment nodes may read the same verified events under different rules. Applicability, open deadlines and semantic uncertainty are stored separately.

Internal T/F/U condition values do not map directly to MET/NOT_MET/UNCERTAIN: a false completion condition can still mean PENDING before a deadline. A delivery dispute may require review without deciding that the student failed.

Evidence identity and delivery are part of the algorithm

  "event_type": "medication_instruction",

  "stance": "adopted",
  "corrects": ["s001.t05.e01"],
  "input_quality": "clear",
  "asr_confidence": null
}

Null ASR confidence means the provider did not supply it; an LLM’s subjective certainty is not an ASR confidence score. Extracting atomic events does not mean reading each sentence in isolation: recent context is needed for pronouns and references.

Keep distinct draft, reserved, sent, confirmed-delivered, partial and uncertain-delivery states. Reservation prevents duplicate prompts but is not exposure. Release failed reservations. Count only confirmed delivered content when applying a prompt consequence; preserve ambiguous delivery for review. Never turn an intercepted leakage draft into student exposure.

Explicit corrections update the current advice while retaining actual earlier errors. A student utterance is evidence of performance, not automatically an approved clinical fact.

Incremental execution avoids an unnecessary chain of model calls

Compile rules and load knowledge before the session. Extract new events once, execute only affected rule dependencies, and project permissions for the shared role generator. A model call is reserved for semantics or generation, while counts, joins, rule composition and replay use ordinary code.

Audit the actual draft against a platform-owned permission snapshot. Stream no unchecked answer to the learner. Use bounded retries or a safe in-role fallback; record failures. Final explanation occurs after the encounter and cannot overwrite deterministic decision fields.

Time and token costs must be measured on the implemented platform. The architecture does not promise zero latency or a fixed percentile.

Select evidence without discarding the source

  1. Store immutable source spans once; refer to them by ID rather than repeating several transcript copies.
  2. Retrieve the active rule’s prerequisite closure, medication conditions and relevant evidence, with permission-aware projection.
  3. Retain original-text lookup and expand context if reference resolution is uncertain.
  4. Record per-call tokens, cumulative usage, model identity and truncation/rejection events.
  5. Verify incremental execution against a full replay at a frozen version.

The historical audit measures reconstructed requests with a reference tokenizer. It is not measured graph compression or evidence of a live model’s context limit.

Frozen input records and the analysis protocol determine the denominators. Repeated runs, diagnosis variants and ablations carry separate task tags and do not add independent observations.

Mode is trusted-server state, not a student option

Assign conventional_rag or egj when the server creates the session. Preserve it through begin, commit, resume and report caching. Reject client attempts to change it. The shared interface does not expose method labels or permit switching midway through an encounter.

A does not load B’s compiled rule graph; it retains the original station controls and performs its conventional assessment. B persists the frozen graph version and evidence/session state. Shared caches include mode, case/history, model/parameters, knowledge/retrieval version and policy version; B adds rule version and state revision.

The current assessment/training setting is a different field and must not be repurposed as research mode. Keep the same public response schema while preserving method-specific audit data on the server.

The ablation is an offline evaluation dependency switch

On the saved full B evidence graph, suppress only the typed links from real role interventions to assessment consequences. Do not change actor permissions, clinical knowledge, student-source tests or correction handling. Log each disabled edge and verify irrelevant decisions remain identical. Ablation task and controls.

Checks before a valid comparative run

  1. Incremental and full replay agree for the same frozen rules/events.
  2. No evidence join crosses the wrong drug, patient or regimen.
  3. Quoted, hypothetical and patient-originated statements cannot earn student credit as adopted student advice.
  4. Before/after tests use span order where two actions occur in the same turn.
  5. Drafts, partial delivery and confirmed prompts produce the intended different state changes.
  6. Corrections retain historical errors; unknown evidence cannot become a confident pass or deduction.
  7. A and B retain the common cases, knowledge and applicable existing protections; mode/cache isolation is checked.
  8. Every failed output appears in the research export and primary denominator.

These are implementation tests, not evidence of clinical or educational superiority.

Reference selection and claim checking

The readings support simulation, graph/temporal judging, pharmacy condition modelling, measurement and controlled educational evaluation. Publisher, proceedings and author-public versions are identified on each reading page. This is a focused, auditable related-work collection, not an exhaustive systematic review.

Check close preprints and method claims before submission. Do not identify an observed disclosure problem with a proven causal effect of architecture. The final bibliography includes only papers actually cited; archive-only material is not forced into the manuscript. Attachment review and corrections.
