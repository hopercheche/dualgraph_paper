A · Conventional AI OSCE + RAG

The role model interprets source role instructions, retrieved clinical context and delivered history during the consultation. Afterward, an assessment model reads the full history, source rubric and relevant knowledge. Quote-integrity and schema checks remain shared infrastructure.

B · DualGraph-OSCE

The same materials are compiled into a Rule Graph. Delivered acts update the Evidence Graph. Semantic matching proposes rule alignments; deterministic execution produces role permissions and current assessment states. The Evidence-Graph Judge is the execution core of DualGraph-OSCE.

This is an implementation specification, not evidence of validated performance. The code already contains some hybrid constraints; the mode boundary must be audited so that A is described honestly.

Clinical retrieval is role-aware

Do not give a lay patient the examiner’s full teaching key. Patient facts, role permissions and assessment-only professional knowledge must have explicit access views in both methods. A shared retrieval candidate pool can produce different authorised views without giving B additional knowledge.

Backend-owned mode, fixed for the session

Select mode=conventional_rag or mode=egj from a trusted server assignment when creating the session. The frontend does not select or display it. Reconnect, preparation and assessment read the frozen session mode; changing the environment default cannot change an existing session.

Persist the model versions, case/rubric/knowledge versions, Rule Graph version for B, event revision and allocation identifier. Include mode and revision in all cache identities. Never reuse a reply or assessment cache from the other mode.

A malformed or absent mode must follow a defined server policy, not allow silent migration during an experiment. The shared report adapter must preserve unresolvable/review outcomes rather than manufacture a normal grade.

Two graphs and two projections

Rule Graph: approved constraints

Keep role and assessment rules as separate nodes. Compile their trigger logic, AND/OR combinations, time boundaries, medication conditions and consequences from the approved station documents. Link both rule types to shared event prerequisites; do not merge permissions and rubric criteria into one node.

Evidence Graph: delivered events

Each event has speaker, source span, time/order, action type, medicine/patient/regimen bindings and delivery status. Relations include repetition, correction and prompted completion. An unsent draft is not student-exposed evidence.

One execution state, separate outputs

ProjectionOutput
Role permissionsRequired answer, allowed answer, prohibited disclosure, permitted prompt and consumed-prompt state.
Assessment stateRequirement completion, applicable consequences, corrected/unresolved error history and review-reason sets.

Transcription uncertainty, unknown clinical mappings or missing rules produce an explicit unresolved state. Deterministic replay guarantees the same rule result for the same graph and version; it does not guarantee correct extraction or clinical truth.

MTX: one sourced sequence, several distinct decisions

A prompt draft is not a delivered prompt

Onychomycosis: if the authorised interaction prompt is merely prepared, it neither consumes the prompt nor activates the C+ consequence. If the student actually receives it and then explains the interaction, completion and the cap coexist. If an unauthorised answer is delivered, mark system intervention and refer the affected assessment to faculty; do not automatically award or deduct student credit.

For interrupted TTS, retain the exact sent or acknowledged playback range and the quality of that delivery evidence. Server transmission does not prove the student heard every word.

Acceptance tests and research exports

  • Mode remains fixed through retries, reconnects and server default changes; caches do not cross modes.
  • A and B share model/resources and a frozen input prefix in the paired benchmark.
  • An unsent prompt draft does not activate consequences; a delivered authorised prompt does.
  • MTX correction keeps the original error and speaker attribution.
  • Misbound medication instructions cannot satisfy a different drug’s criterion.
  • Missing/uncertain input triggers explicit uncertainty and review rather than invented normal results.
  • The same frozen Evidence Graph and Rule Graph replay produces the same B decisions.
  • Single-relation ablation does not alter source events, medicine bindings or correction logic.

Export first replies, rule decisions, source spans, versions and failures. Faculty references remain separate. The technical target is 120 checkpoints, 30 per station, with source-cluster analysis. Student feedback is a separate experience outcome.
