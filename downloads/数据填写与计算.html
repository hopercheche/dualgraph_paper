RESEARCH AND STUDY MATERIALS

Data recording and metric calculation

One source manifest, two primary decisions and auditable paired results.

Start with the source record

The technical target is 120 frozen decision checkpoints, balanced as 30 per station. The final manifest must identify each source recording and cutoff. The planned source is 16 live consultation recordings; these recordings and the 120-checkpoint faculty-labelled benchmark must still be assembled and verified.

Do not use an old scenario template as if it were an approved dataset. Maintain one authoritative manifest and record every exclusion, failed run and unresolved reference.

Use fixed codes

Requirement states must distinguish completed, not completed at the relevant evaluation boundary, pending during an ongoing consultation and uncertain. Keep the chosen machine-code schema identical for A/B. Consequences use approved fixed codes; a comparison to free-text paraphrases is not a reliable exact match.

Use an empty applicable-effect set ([]) when no consequence applies; a displayed NONE is only its human-readable shorthand. Use NO_ERROR, UNRESOLVED or CORRECTED_HISTORY_RETAINED for the relevant revision state; and a review-needed flag plus its normalized review-reason set. Applicability is fixed before running; absence itself remains testable when the reference is an empty set. Store effects as applicable_effects_json, correction as correction_state and review reasons as review_reasons_json in the canonical checkpoint reference.

Store the original quote, source span and reason for every non-compliant role check or disagreement. A missing system row is a failed run, not an invitation to shrink the denominator.

From records to results

  1. Validate one reference and one A/B output for each frozen checkpoint, including failures. Role output is the finalized response after the prespecified audit/retry policy within the first scheduled run, not a hand-picked repeat or necessarily a played audio event.
  2. Calculate the role and assessment 0/1 flags separately.
  3. For each method, divide successful flags by all eligible prespecified checkpoints. If all 120 are eligible and run, the denominator is 120 per method.
  4. Report the paired percentage-point difference, the four A/B pass/fail cells and uncertainty with resampling by source recording (and participant where relevant).
  5. Apply the prespecified correction for the two primary endpoints. Use an independence-based paired test only when its assumptions are satisfied.
  6. Replay the same evidence with the one-edge-class ablation; verify that non-target processing is unchanged. List affected records and negative controls.
  7. Report live-use completeness, faults and survey items separately from technical benchmark accuracy.

Use the current paired cluster-analysis utility with the outcome template. The independent-cluster ID is mandatory. Earlier analysis utilities are superseded by this protocol. A script accepting a file does not prove that its labels are faculty-verified.
