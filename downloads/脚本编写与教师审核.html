Preparing frozen dialogue checkpoints

Record provenance, cutoffs, applicable rules and an independent reference.

What one benchmark record contains

A checkpoint is a frozen portion of a consultation at a predefined decision point. It includes the station version, the source recording ID, the delivered history up to the cutoff and the rules being checked. Both systems receive the same permitted input. A recording may provide several checkpoints, but these are not independent participants.

A prefix means all earlier dialogue through that cutoff. “Stop after E4” means supply E1–E4 and withhold E5 onward. A repeated run uses the same prefix again; a diagnostic variant changes the input and stays attached to the same source record.

How to prepare the record

FieldMeaning / example
checkpoint_idUnique frozen decision point; do not reuse it for an unrelated record.
source_recording_id / participant_cluster_idProvenance and analysis cluster. Never fabricate these identifiers for illustrative examples.
case_id / rule_graph_versionC1–C4 and the exact approved station-rule snapshot.
cutoff / prefix_textLast delivered utterance and the complete earlier history. Future corrections cannot appear in an earlier role test.
primary_criterionThe one prespecified decision evaluated at this checkpoint, with any applicable linked consequences.
role_must / role_forbiddenRequired and prohibited behaviour at that moment. Optional allowed behaviour is recorded separately.
prompt delivery / correction pointersOriginal event, speaker, delivered status and related student answer or correction. A generated draft is not a delivered prompt.
reference fields and applicabilityFaculty state, consequence, revision and review values, fixed before predictions.
freeze metadataInput hash, rules and knowledge versions, approval status and freeze time.

What faculty review establishes

The station documents already say how to assess. Faculty check whether the selected evidence actually meets those requirements: who supplied the information, which drug and patient it applies to, whether a prompt was heard and whether the student corrected an adopted error. Review the full context when a short prefix is ambiguous.

An unresolved transcript or rule interpretation should be marked for review, not silently converted into a clear student error. Development examples are separate from formal checkpoints.

Keep four operations separate

OperationWhat changesCounting rule

Repeated runOnly stochastic output; input and configuration remain fixedDoes not add a new independent checkpoint.
